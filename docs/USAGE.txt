txtmux —— 多路 TXT 记录 → 本地端口 转发器（图形界面）
======================================================

和 txtdial 的区别：txtdial 一次只管一条记录（命令行），txtmux 是带界面的管理器，
可以同时配置并运行**多条**「TXT 记录 / 入口 URL + 本地端口」的转发规则。

两种取值方式（在「TXT 记录」那个输入框里填什么都行）：

1. **TXT 记录名**（如 `open.example.com`）—— 查 TXT 拿 `ip:端口`
2. **入口 URL**（`http://` / `https://` 开头，如 `https://webdav.example.com/`）
   —— 用 WinHTTP 请求它、自动跟随 307/302，取**跳转后**的 `host:端口`

第 2 种就是「本地代理 web 服务的 STUN 端口、直接访问不跳转」：
web 入口会 307 到一个随机 STUN 端口（每次变），txtmux 帮你把它变成一个固定的本地端口。

文件
----
- txtmux32.exe   32 位，XP SP1 ~ Windows 11（32/64 位系统都能跑，推荐先用这个）
- txtmux64.exe   64 位，XP x64/2003 及以后
- txtmux.ini     配置（首次运行后自动生成，和 exe 同目录）
- src/           源码（单文件 C，含构建脚本）

界面
----
```
TXT 记录 [open.example.com        ]  本地端口 [9000 ]  [添加]

open.example.com            :9000    运行中 → 198.51.100.20:18000
frps.example.com            :7000    运行中 → 198.51.100.20:18001
webdav.example.com          :8443    已停止

[删除所选] [启动全部] [停止全部]   [x] 启动时自动连接     2/3 运行
┌──────────────── 日志 ────────────────────────────────┐
│ 17:02:11 [open.example.com] 已监听 127.0.0.1:9000      │
│ 17:02:11 open.example.com -> 198.51.100.20:18000       │
└──────────────────────────────────────────────────────┘
```

- 输入记录名和端口 → 「添加」；最多 32 条，端口不能重复，记录也不能重复
  （TXT 记录输入框默认是空的，不再预填）
- 列表每 2 秒刷新，每条规则显示：运行中 → 当前目标地址 / 已停止 / 已禁用
- **单条开关**：选中一条后点「启用所选」（同时启动）/「停用所选」（停止），
  也可以直接在列表里**双击**该条来回切换
- 被停用的规则不会参与「全部启动」，也不会参与「启动时自动连接」，但配置仍然保留
- 「删除」会先停掉那条规则再移除
- 「启动时自动连接」勾选后，下次打开程序自动启动所有**启用中**的规则
- 关闭窗口会先停止全部规则再退出

行为
----
- 每条规则独立监听 127.0.0.1:<端口>，收到连接后查自己的 TXT，连过去做双向转发
- TXT 解析结果按规则缓存 30 秒；解析失败沿用上一次成功的地址
- **已在传输的连接不会被重新解析打断**，只有新连接才用新地址
- 只支持 TXT 里是 `host:port` 或 `[ipv6]:port`；没有端口的记录会报错跳过
- 目标连接目前走 IPv4（`getaddrinfo` 指定 AF_INET），所以 TXT 里给 IPv6 字面量不会被使用

配置
----
`txtmux.ini`（INI 格式，XP 自带 API 读写，UTF-16）：

```ini
[main]
autostart=1
count=2
[rules]
rule1=open.example.com 9000 1
rule2=frps.example.com 7000 0
```

规则行格式：`记录名 本地端口 [启用]`，第三段 `0` 表示禁用（省略视为启用，兼容旧配置）。

兼容性
------
- 32 位版 PE32 / 子系统 4.0，导入表只有 `DNSAPI / GDI32 / KERNEL32 / msvcrt / USER32 / WS2_32`
  （全是 XP 自带），`-static` 静态链接，不需要 VC 运行库和额外 DLL
- TXT 查询用 `DnsQuery_W`（XP SP1+）；高 DPI 用动态 `GetProcAddress`，XP 上自动跳过
- 64 位版 PE32+ / 子系统 5.2

已验证 / 未验证
---------------
- 已验证：`parse_url` 的 7 个用例（https/http、带端口、带路径查询串、缺主机、端口 0、非 http 协议）
- 已验证：`parse_rule_line` 的 7 个用例（两段旧格式、带禁用标记、带空白、缺端口、端口越界、空串）
  在 Linux 上单独跑过；`parse_endpoint` 的 8 个用例在 Linux 上单独跑过（IPv4、域名、`[v6]:port`、带空白、
  缺端口、裸 IPv6、空串、端口越界），并因此修掉一个真实 bug —— `[v6]:port` 解析时把 `]`
  一起算进了主机名
- 未验证：Windows 上的窗口与多路中继的实际运行（开发环境没有 Windows 机器）。
  如果窗口或转发有问题，把日志框里的内容发我

构建
----
```sh
# 需要 mingw-w64
sh build.sh     # 已链接 -lwinhttp
```

（源码与 ovpnwrap 的 C 版共用同一套写法：`DnsQuery_W` 查 TXT、`select` + 每连接一个线程做转发。）
