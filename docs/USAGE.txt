txtmux —— 多路 TXT/入口 URL → 本地端口 转发器（图形界面）
=========================================================

一次可以配置并运行**多条**转发规则。每条规则的地址来源有两种填法：

1. **TXT 记录名**（如 `open.example.com`）—— 查 TXT 拿 `ip:端口`
2. **入口 URL**（`http://` / `https://` 开头，如 `https://webdav.example.com/`）
   —— 用 WinHTTP 请求它、自动跟随 307/302，取**跳转后**的 `host:端口`

第二种就是「把 web 服务的动态 STUN 端口变成固定入口」用的。

文件
----
- txtmux32.exe   32 位，XP SP2 ~ Windows 11（32/64 位系统都能跑，推荐先用这个）
- txtmux64.exe   64 位，XP x64/2003 及以后
- txtmux.ini     配置（首次运行后自动生成，和 exe 同目录）
- src/           源码（txtmux.c + res.rc + build.sh）

界面
----
```
TXT 记录 / 入口 URL [https://webdav.example.com/   ]  本地端口 [8443]  [添加]

https://webdav.example.com/            :8443   运行中 → 203.0.113.10:50000
frps.example.com                       :7000   运行中 → 198.51.100.20:18001
open.example.com                       :9000   已禁用

[启用所选] [停用所选] [删除]  [全部启动] [全部停止]  [x] 启动时自动连接   2/3 运行
┌──────────────── 日志 ────────────────────────────────┐
│ 02:38:11 [webdav] 已监听 127.0.0.1:8443
│ 02:38:11 跟随跳转: https://webdav.gw.example.com:50000/
└──────────────────────────────────────────────────────┘
```

- 最多 32 条；端口不能重复，记录/URL 也不能重复
- 单条启用/停用：选中后点按钮，或**双击列表项**切换；停用的规则不参与「全部启动」
- 列表每 2 秒刷新：运行中 → 当前目标 / 已停止 / 已禁用

让网页访问不跳转（推荐：本地代理模式，不动 DNS）
-----------------------------------------------
`https://webdav.example.com/` 会 307 跳到 `https://webdav.gw.example.com:<随机端口>/`，
端口每次 STUN 重建都会变。把它变成固定入口的正确做法是**本地代理**，不要改 hosts：

1. ini 里打开代理：

   ```ini
   [main]
   proxy=8080
   bind=127.0.0.1
   ```

2. 浏览器 / 系统代理设为 `127.0.0.1:8080`（HTTP 代理，HTTPS 走 CONNECT，浏览器自动处理）

3. 规则里「TXT 记录」填 `https://webdav.example.com/`，本地端口随便填（代理模式不依赖它）

4. 浏览器直接访问 `https://webdav.gw.example.com/`（默认 443，不需要带端口）

过程：浏览器发 `CONNECT webdav.gw.example.com:443` → txtmux 认出这条域名属于那条 URL
规则 → 解析入口、跟随 307 拿到真实端点（如 `203.0.113.10:50000`）→ 直连 → 回
`200 Connection established` → 浏览器与真实端点做端到端 TLS（证书 `*.gw.example.com`
匹配）。全程没有 307，**也没有改动任何 DNS 记录**。

- 只有匹配到规则的域名会被改写，其他域名代理会直接直连（可以当普通代理用）
- 支持 `HTTP CONNECT` 和 `SOCKS5`（no-auth）两种协议
- `*.gw.example.com` 是双栈的，这种模式完全不碰 AAAA，IPv6 访问照旧

### 为什么不建议用 hosts

hosts 只按名字覆盖解析：写一行 `127.0.0.1  webdav.gw.example.com` 会把该名字的
AAAA 一起顶掉，走 IPv6 的访问就断了（本程序也只监听 IPv4，写 `::1` 也没用）。
代理模式没有这个问题。

### 泛域名（*.gw.example.com）怎么配

每条规则多了一个可选的**「匹配域名」**（支持 `*` 通配），这样"客户端访问的名字"和
"端口从哪来"就可以分开指定。

匹配优先级：① 匹配域名字段 → ② 入口 URL 的域名 → ③ 解析出来的目标域名 → ④ 都没命中就直连。

界面第 2 行填「匹配域名」，或者在 ini 里写第 4 段：

```ini
[rules]
; webdav：入口会 307，跟随它；客户端访问 webdav.gw.example.com
rule1=https://webdav.example.com/   8443  1  webdav.gw.example.com
; 另一个 web 服务（有自己的入口）
rule2=https://git.example.com/      8444  1  git.gw.example.com
; 端口只存在 TXT 里的 TCP 服务
rule3=open.example.com              9000  1  open.gw.example.com
; 一条通配规则：任意一层子域都指向同一个端点（同一服务多个别名时用）
rule4=https://webdav.example.com/   8445  1  *.gw.example.com
```

要点：

- **一个端点一条规则**：泛域下不同子域对应不同服务，必须各写一条；通配符解决的是
  "同一服务的多个名字"，不是"多个服务共用一个端口"
- 通配语法：`*` 匹配任意字符（含点）。`*.gw.example.com` 覆盖
  `webdav.gw.example.com`、`a.b.gw.example.com`，但**不含**裸域
  `gw.example.com`；要连裸域就再加一条 `gw.example.com`
- v2ray 那边的路由可以写宽（`domain:gw.example.com`）：命中的走 txtmux，
  没命中的 txtmux 会**直接直连**（出站按目标自身的 A/AAAA 选择，IPv6 不会被降级）

### 把 txtmux 当系统代理（链式到 v2rayN，全机生效）

v2rayN 的 `bin/config.json` 是它每次启动重新生成的，**手改一定会被覆盖**；它的界面里也不方便
加自定义出站。所以换个方向：让 txtmux 占系统代理，未命中的流量**链式交给 v2rayN**。

1. v2rayN：关掉「自动配置系统代理」（参数设置里），别让它再抢系统代理
2. Windows：设置 → 网络和 Internet → 代理 → 手动设置 → `127.0.0.1:8080`
3. txtmux 的 ini：

   ```ini
   [main]
   proxy=8080
   upstream=127.0.0.1:10809        ; v2rayN 的 HTTP 入站（不是 SOCKS 的 10808）
   bind=127.0.0.1
   [rules]
   rule1=https://webdav.example.com/ 8443 1 webdav.gw.example.com
   ```

效果：

- 命中规则的域名（webdav）→ txtmux 直连真实 STUN 端点，无 307
- **其他所有域名** → txtmux 用 CONNECT 转给 `upstream`（v2rayN），照旧走代理，全机的程序都适用
- 不再依赖 PAC，也不用改 v2ray 的任何配置

注意：

- 跟随 307 用的是 **WinHTTP 直连**（`WINHTTP_ACCESS_TYPE_NO_PROXY`）。这一点很关键：
  如果让它走系统代理，而系统代理正是 txtmux 自己，就会形成自指循环、入口永远解析不出来
- 上游失败时的行为由 `upstreamFallback` 决定：
  - `direct`（默认）：退回直连，并在日志里打 `WARN 上游 ... 不可用，改为直连`
  - `block`：拒绝连接（返回 502），宁可不通也不让本该走代理的流量泄漏
- 想让"未命中的直接直连"就留空 `upstream`
- v2rayN 用 TUN 模式时，回环地址（127.0.0.1）一般不会被 TUN 接管，上面这套照常工作；
  但 txtmux 直连真实端点的那条出站会被 TUN 捕获，如果它绕远了，就在 v2ray 路由里给
  目标 IP 加 `direct`

### 和 v2rayN / 其他代理客户端共存

Windows 上「系统代理」只有一个位置，v2rayN 会占着它并定期回写，所以**不要把 txtmux 设成系统代理**，
用 PAC 分工：

1. ini：

   ```ini
   [main]
   proxy=8080
   upstream=127.0.0.1:10809     ; v2rayN 的 HTTP 入站端口
   ```

2. 浏览器代理设置选「自动配置脚本 / PAC」，填：

   ```
   http://127.0.0.1:8080/proxy.pac
   ```

3. txtmux 生成的 PAC 长这样（按你的规则动态生成）：

   ```js
   function FindProxyForURL(url, host) {
     if (host == "webdav.gw.example.com") return "PROXY 127.0.0.1:8080;";
     if (host == "webdav.example.com") return "PROXY 127.0.0.1:8080;";
     return "PROXY 127.0.0.1:10809; DIRECT";   // 其余照常走 v2rayN
   }
   ```

于是：命中规则的域名由 txtmux 直连真实 STUN 端点，**其他所有站点照旧经过 v2rayN**，互不干扰。

注意几点：

- `upstream` 留空时兜底是 `DIRECT`（全部直连），那样其他站点就不走 v2ray 了，记得填上
- 如果 v2rayN 用 **TUN/系统代理全接管** 模式，txtmux 自己的出站会被拦截：目标是国内地址时通常能通，
  但会绕一圈。更稳妥的是在 v2ray 的路由规则里给 `203.0.113.10` 或
  `domain:gw.example.com` 加 `direct`
- txtmux 不做上游代理转发：它自己直连目标，`upstream` 只用在 PAC 兜底里
- 浏览器以外、只会读系统代理的程序：要么临时切系统代理，要么用能设 PAC 的客户端

### 代理模式的限制

- 只做 CONNECT 隧道 + SOCKS5 no-auth；不解析明文 HTTP 内容（不缓存、不改包）
- SOCKS5 目标只处理 IPv4 与域名，`ATYPE=IPv6` 的请求会被拒绝
- 需要客户端支持设置代理（浏览器、curl 都行；部分系统级软件不行）

行为
----
- 每条规则独立监听 `bind:<本地端口>`；收到连接后查自己的来源地址并转发
- 解析结果按规则缓存 30 秒；解析失败沿用上一次成功的地址
- 已建立的连接不会被重新解析打断，只有新连接用新地址
- TXT 值的格式必须是 `host:port` 或 `[ipv6]:port`
- 目标建连走 IPv4（`getaddrinfo` 指定 AF_INET）
- URL 模式用 WinHTTP 跟随跳转，**XP 需 SP2 及以上**（Win7+ 自带）；HTTPS 证书错误会被忽略
  （只用来读最终地址）

配置（txtmux.ini）
------------------
```ini
[main]
autostart=1
bind=127.0.0.1      ; 改成 0.0.0.0 可让局域网设备使用
proxy=8080          ; >0 时额外起 HTTP CONNECT / SOCKS5 代理，0 = 关闭
count=2
[rules]
rule1=https://webdav.example.com/ 8443 1
rule2=open.example.com 9000 0
```

规则行：`来源 本地端口 [启用]`；第三段 `0` 表示禁用（省略视为启用，兼容旧配置）。

兼容性
------
- 32 位版 PE32 / 子系统 4.0，导入表只有
  `DNSAPI / GDI32 / KERNEL32 / USER32 / WINHTTP / WS2_32 / msvcrt`（都是系统自带），
  `-static` 静态链接，不需要 VC 运行库
- 64 位版 PE32+ / 子系统 5.2

已验证 / 未验证
---------------
- 已验证（纯逻辑在 Linux 上单独抽出来跑）：
