txtmux —— 多路 TXT/入口 URL → 本地端口 转发器（图形界面）
=========================================================

一次可以配置并运行**多条**转发规则。每条规则的地址来源有两种填法：

1. **TXT 记录名**（如 `open.example.com`）—— 查 TXT 拿 `ip:端口`
2. **入口 URL**（`http://` / `https://` 开头，如 `https://webdav.example.com/`）
   —— 用 WinHTTP 请求它、自动跟随 307/302，取**跳转后**的 `host:端口`

第二种就是「把 web 服务的动态 STUN 端口变成固定入口」用的。

文件
----
- txtmux32.exe   32 位，XP SP2 ~ Windows 11（32/64 位系统都能跑，推荐先用这个）
- txtmux64.exe   64 位，XP x64/2003 及以后
- txtmux.ini     配置（首次运行后自动生成，和 exe 同目录）
- txtmux.log     运行日志（UTF-8，和 exe 同目录，追加写；界面上那份日志只是内存副本）
- txtmux-YYYYMMDD.log  按天归档的旧日志（换天时由 txtmux.log 改名而来，见「日志切分」）
- txtmux.ico     程序图标（16/32/48，编译时由 res.rc 打进 exe；tools/mkicon.py 可重新生成）
- src/           源码（txtmux.c + res.rc + build.sh）

界面
----
```

https://webdav.example.com/            :8443   运行中 → 203.0.113.10:50000
frps.example.com                       :7000   运行中 → 198.51.100.20:18000
open.example.com                       :9000   已禁用

[x] 开机自启   [x] 关闭时最小化到托盘
[启用所选] [停用所选] [删除]  [全部启动] [全部停止]  [x] 启动时自动连接   2/3 运行
```

- 最多 32 条；端口不能重复，记录/URL 也不能重复
- 单条启用/停用：选中后点按钮，或**双击列表项**切换；停用的规则不参与「全部启动」
- 列表每 2 秒刷新：运行中 → 当前目标 / 已停止 / 已禁用

让网页访问不跳转（推荐：本地代理模式，不动 DNS）
-----------------------------------------------
`https://webdav.example.com/` 会 307 跳到 `https://webdav.gw.example.com:<随机端口>/`，
端口每次 STUN 重建都会变。把它变成固定入口的正确做法是**本地代理**，不要改 hosts：

1. ini 里打开代理：

   ```ini
   [main]
   proxy=8080
   bind=127.0.0.1
   ```

2. 浏览器 / 系统代理设为 `127.0.0.1:8080`（HTTP 代理，HTTPS 走 CONNECT，浏览器自动处理）

3. 规则的来源填 `stun.example.com`（TXT 里就是真实 `ip:端口`），**第 4 段填客户端要访问的域名**：

   ```ini
   [rules]
   rule1=stun.example.com 8443 1 webdav.gw.example.com
   ```

   来源也可以直接写入口 URL（`https://webdav.example.com/`），第 4 段同样要写；不写第 4 段
   的规则只做本地端口转发，不会被代理命中（见下文「四种用法」）。

4. 浏览器直接访问 `https://webdav.gw.example.com/`（默认 443，不需要带端口）

过程：浏览器发 `CONNECT webdav.gw.example.com:443` → txtmux 用**第 4 段**命中这条规则
→ 查 `stun.example.com` 的 TXT（或跟随入口的 307）拿到真实端点（如 `203.0.113.10:50000`）
→ 用它替换客户端给的 443 后直连 → 回 `200 Connection established` → 浏览器与真实端点做端到端
TLS（证书 `*.gw.example.com` 匹配）。客户端全程不需要知道真实端口，**也没有改动任何 DNS**。

- 只有匹配到规则的域名会被改写，其他域名代理会直接直连（可以当普通代理用）
- 支持 `HTTP CONNECT` 和 `SOCKS5`（no-auth）两种协议
- `*.gw.example.com` 是双栈的，这种模式完全不碰 AAAA，IPv6 访问照旧

### 为什么不建议用 hosts

hosts 只按名字覆盖解析：写一行 `127.0.0.1  webdav.gw.example.com` 会把该名字的
AAAA 一起顶掉，走 IPv6 的访问就断了（本程序也只监听 IPv4，写 `::1` 也没用）。
代理模式没有这个问题。

### 四种用法（第 4 段决定要不要参与代理分流）

每条规则是 `来源 本地端口 [启用] [匹配域名]`。**第 4 段不写 = 只做端口转发**，这条规则不参与
代理的域名匹配，也不会出现在 PAC 里；写了第 4 段才会被代理按域名命中。

| 第 4 段 | 模式 | 干什么 | 客户端怎么用 |
|---|---|---|---|
| 不写 | **① 端口转发** | 只在 `bind:<本地端口>` 监听，有连接就查 TXT/跟随 URL 转发 | 直连 `127.0.0.1:<本地端口>` |
| 精确域名 | **② 域名分流** | 访问该域名时改连这条规则解析出的端点 | 走 `127.0.0.1:8080` 代理 |
| `*` 通配 | **③ 通配分流** | 一条覆盖多层子域（一个网关挂多个服务时用） | 同上 |
| 不写（来源是 URL） | **④ 跟随 307 的端口转发** | 入口每次 307 换端口也自动跟上 | 直连本地端口 |

```ini
[rules]
; ① 纯端口转发：只暴露 127.0.0.1:9000，代理不认 open.gw.example.com
rule1=open.example.com 9000 1

; ② 域名分流：客户端访问 webdav.gw.example.com 时改连 TXT 里的端口
rule2=stun.example.com 8443 1 webdav.gw.example.com

; ③ 通配分流：网关后面的一堆服务（webdav、router……）一条全覆盖
rule3=stun.example.com 8444 1 *.gw.example.com

; ④ 入口 URL + 端口转发：跟随 307 拿端口，客户端只认 127.0.0.1:8445
rule4=https://dav.example.com/ 8445 1
```

怎么选：

- 一个 STUN 端口后面是**按 SNI 分发的网关**（同一个端口上 `webdav.*` 是 Apache、
  `router.*` 是 LuCI 登录页）→ 用 **③**
- 服务各自独立端口、客户端也只用自己那一个域名 → 用 **②**
- **纯 TCP 服务（不是 HTTPS）** → 只能用 **①**：代理只做 CONNECT 隧道，域名分流对非 TLS 的
  端口没有意义（例如 `open` 的 `:50002` 既不应答 HTTP 也不做 TLS）
- 入口 URL 会反复变端口（307/STUN）→ 用 **④**，或 ② 配 TXT

界面第 2 行的「匹配域名(可选，支持 *)」就是这第 4 段。

### 泛域名与网关型服务

要点：

- **顺序决定谁先命中**：txtmux 按规则顺序取第一条命中的，所以「精确规则」要写在「通配规则」之前
- **一条 STUN 端口后面挂着网关时，通配才是对的**：同一个端口会按 SNI 分给多个后端
  （实测 `:50000` 上 `router.gw.example.com` → OpenWrt LuCI 返回 403、
  `webdav.gw.example.com` → Apache 404），这种情况一条 `*.gw.example.com`
  就能覆盖全部服务
- **通配的陷阱**：网关不认识某个 SNI 时会 307 到 `<你的SNI>.gw.example.com:同一端口>`
  （会再叠一层 `gw`，实测 `open.gw...` → `open.gw.gw...`）。
  浏览器跟着 307 再连还是 `*.gw`，会再次命中通配 → 又回网关 → 死循环。
  所以不在这个网关上的服务，要么只用 ① 端口转发，要么给它写 ② 精确规则并放在通配之前
- 通配语法：`*` 匹配任意字符（含点）。`*.gw.example.com` 覆盖
  `webdav.gw.example.com`、`a.b.gw.example.com`，但**不含**裸域
  `gw.example.com`；要连裸域就再加一条 `gw.example.com`
- v2ray 那边的路由可以写宽（`domain:gw.example.com`）：命中的走 txtmux，
  没命中的 txtmux 会**直接直连**（出站按目标自身的 A/AAAA 选择，IPv6 不会被降级）

### 把 txtmux 当系统代理（链式到 v2rayN，全机生效）

v2rayN 的 `bin/config.json` 是它每次启动重新生成的，**手改一定会被覆盖**；它的界面里也不方便
加自定义出站。所以换个方向：让 txtmux 占系统代理，未命中的流量**链式交给 v2rayN**。

1. v2rayN：关掉「自动配置系统代理」（参数设置里），别让它再抢系统代理
2. Windows：设置 → 网络和 Internet → 代理 → 手动设置 → `127.0.0.1:8080`
3. txtmux 的 ini：

   ```ini
   [main]
   proxy=8080
   upstream=127.0.0.1:10809        ; v2rayN 的 HTTP 入站（不是 SOCKS 的 10808）
   bind=127.0.0.1
   [rules]
   rule1=https://webdav.example.com/ 8443 1 webdav.gw.example.com
   ```

效果：

- 命中规则的域名（webdav）→ txtmux 直连真实 STUN 端点，无 307
- **其他所有域名** → txtmux 用 CONNECT 转给 `upstream`（v2rayN），照旧走代理，全机的程序都适用
- 不再依赖 PAC，也不用改 v2ray 的任何配置

注意：

- 跟随 307 用的是 **WinHTTP 直连**（`WINHTTP_ACCESS_TYPE_NO_PROXY`）。这一点很关键：
  如果让它走系统代理，而系统代理正是 txtmux 自己，就会形成自指循环、入口永远解析不出来
- 上游失败时的行为由 `upstreamFallback` 决定：
  - `direct`（默认）：退回直连，并在日志里打 `WARN 上游 ... 不可用，改为直连`
  - `block`：拒绝连接（返回 502），宁可不通也不让本该走代理的流量泄漏
- 想让"未命中的直接直连"就留空 `upstream`
- v2rayN 用 TUN 模式时，回环地址（127.0.0.1）一般不会被 TUN 接管，上面这套照常工作；
  但 txtmux 直连真实端点的那条出站会被 TUN 捕获，如果它绕远了，就在 v2ray 路由里给
  目标 IP 加 `direct`

### 和 v2rayN / 其他代理客户端共存

Windows 上「系统代理」只有一个位置，v2rayN 会占着它并定期回写，所以**不要把 txtmux 设成系统代理**，
用 PAC 分工：

1. ini：

   ```ini
   [main]
   proxy=8080
   upstream=127.0.0.1:10809     ; v2rayN 的 HTTP 入站端口
   ```

2. 浏览器代理设置选「自动配置脚本 / PAC」，填：

   ```
   http://127.0.0.1:8080/proxy.pac
   ```

3. txtmux 生成的 PAC 长这样（按你的规则动态生成）：

   ```js
   function FindProxyForURL(url, host) {
     if (host == "webdav.gw.example.com") return "PROXY 127.0.0.1:8080;";
     if (host == "webdav.example.com") return "PROXY 127.0.0.1:8080;";
     return "PROXY 127.0.0.1:10809; DIRECT";   // 其余照常走 v2rayN
   }
   ```

于是：命中规则的域名由 txtmux 直连真实 STUN 端点，**其他所有站点照旧经过 v2rayN**，互不干扰。

注意几点：

- `upstream` 留空时兜底是 `DIRECT`（全部直连），那样其他站点就不走 v2ray 了，记得填上
- 如果 v2rayN 用 **TUN/系统代理全接管** 模式，txtmux 自己的出站会被拦截：目标是国内地址时通常能通，
  但会绕一圈。更稳妥的是在 v2ray 的路由规则里给 `203.0.113.10` 或
  `domain:gw.example.com` 加 `direct`
- txtmux 不做上游代理转发：它自己直连目标，`upstream` 只用在 PAC 兜底里
- 浏览器以外、只会读系统代理的程序：要么临时切系统代理，要么用能设 PAC 的客户端

### 代理模式的限制

- 只做 CONNECT 隧道 + SOCKS5 no-auth + 明文 http 转发；不解析、不缓存、不改包
- **明文 `http://` 也支持**：把绝对 URL 改写成 origin-form 后按同一套规则/上游建连，请求头原样
  带过去（去掉 `Proxy-Connection`），响应直接回传。为省掉保活与分包处理，转发时强制
  `Connection: close`，即一条连接一个响应（浏览器会自动重连）
- 指向代理自身端口的明文请求会被 `403` 拒绝（否则会经上游递归回自己）
- SOCKS5 目标只处理 IPv4 与域名，`ATYPE=IPv6` 的请求会被拒绝
- 需要客户端支持设置代理（浏览器、curl 都行；部分系统级软件不行）

行为
----
- 每条规则独立监听 `bind:<本地端口>`；收到连接后查自己的来源地址并转发
- 解析结果按规则缓存 30 秒；解析失败沿用上一次成功的地址
- 已建立的连接不会被重新解析打断，只有新连接用新地址
- TXT 值的格式必须是 `host:port` 或 `[ipv6]:port`
- 目标建连走 IPv4（`getaddrinfo` 指定 AF_INET）
- URL 模式用 WinHTTP 跟随跳转，**XP 需 SP2 及以上**（Win7+ 自带）；HTTPS 证书错误会被忽略
  （只用来读最终地址）

自启动与托盘
------------
界面按钮行上面多一行两个复选框：`[ ] 开机自启`、`[x] 关闭时最小化到托盘`。

### 开机自启

- 勾上 → 写注册表 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`，值名 `txtmux`，
  值是 `"<exe 完整路径>" -min`（带引号，放带空格的中文目录也不会坏）
- 取消勾选 → 删除该值，不留垃圾
- 不需要管理员权限（HKCU），不动计划任务，也不改服务
- `-min` 的意思是**启动后直接缩到托盘**，不弹窗口；想开机就弹窗就别用自启，手动开
- 手动验证注册表：`reg query HKCU\Software\Microsoft\Windows\CurrentVersion\Run /v txtmux`
- 复选框状态每次启动都从注册表读回来，所以"外面手动删了注册表"也不会显示错

### 关闭窗口 = 缩到托盘

默认开着（`closeToTray=1`）。此时：

| 操作 | 结果 |
|---|---|
| 点 × | 窗口隐藏，规则继续转发 |
| 点最小化 | 直接进托盘（不占任务栏） |
| 托盘图标双击 / 左键单击 | 恢复窗口 |
| 托盘图标右键 | 菜单：显示主窗口 / 启动全部规则 / 停止全部规则 / 开机自启 / 退出 |
| 右键菜单「退出」 | 停掉全部规则 → 保存 ini → 删托盘图标 → 退出 |

- 托盘图标悬停提示 `txtmux  N/M 运行`，N 是正在跑的规则数，规则状态变化后会刷新
- 想"关窗口就退出"就取消勾选这个复选框（ini 里变成 `closeToTray=0`）
- 资源管理器（explorer.exe）崩溃重启后，程序会收 `TaskbarCreated` 广播自动把图标加回来
- **单实例**：程序用互斥体 `Local\txtmux_single_instance` 自检。已经有一份在跑（哪怕缩在托盘里），
  再双击 exe 只会把那份的窗口叫到前面然后自己退出，不会出现两个进程抢同一个端口

为什么不把托盘图标做成"关掉窗口就退出、托盘只是提示"：这套程序的用处就是在后台一直转发，
关窗口是常态操作，误关一次端口就断了，比留在托盘更麻烦。

配置（txtmux.ini）
------------------
```ini
[main]
autostart=1
closeToTray=1       ; 1=关闭窗口缩到托盘（默认），0=关闭窗口即退出
bind=127.0.0.1      ; 改成 0.0.0.0 可让局域网设备使用
proxy=8080          ; >0 时额外起 HTTP CONNECT / SOCKS5 代理，0 = 关闭
upstream=127.0.0.1:10808   ; 未命中规则的连接用 CONNECT 转给它（可留空 = 直连）
upstreamFallback=direct    ; 上游连不上时：direct=退回直连并告警，block=直接拒绝
logMaxMB=1024              ; 日志总量上限（MB），0=不限制；超了从最旧的日期开始删
count=2
[rules]
rule1=https://webdav.example.com/ 8443 1 webdav.gw.example.com
rule2=open.example.com 9000 0
```

规则行：`来源 本地端口 [启用] [匹配域名]`；第三段 `0` 表示禁用（省略视为启用，兼容旧配置），
第四段是代理模式下要拦的客户端域名（支持 `*`，可省略）。

ini 里的 `;` 注释：整行注释和写在值后面的行内注释都支持（值会被截到 `;` 之前并去掉尾部空白）。

### 2026-11-18（这版）
代理模式此前**完全没有真正工作过**，四个 bug：

1. **HTTP CONNECT 一律 405**：首行在第二个空格处被截断成 `CONNECT host:port`，却拿去和
   `"CONNECT"` 整体比较，永远不相等，于是每个 CONNECT 都被当成"不支持的请求"回 405。
   浏览器发起的隧道全部在第一步就断了 —— 这就是"日志里一条都没有"的真正原因（405 分支
   在拨号之前就返回了）。现在只比较方法名。
2. **SOCKS5 拒绝 no-auth**：`method == 0x00`（no-auth）被当成"假"值，回 `05 ff` 并断开，
   所有 SOCKS5 客户端都用不了。改用显式的 `offered` 标记。
3. **ini 行内注释污染取值**：`GetPrivateProfileString` 不会剥掉 `; 注释`，于是
   `upstream=127.0.0.1:10808   ; 说明` 整串被当成上游地址，`getaddrinfo` 失败、上游永远
   "不可用"，PAC 里也会带出注释。现在所有取值都过 `ini_str()`，截注释 + 去尾部空白。
4. **规则第 4 段（匹配域名）永远读成 "1"**：解析时没有跳过"启用"字段。后果是
   `*.gw.example.com` 从未生效，而且退出保存把规则写成 `... 1 1`。

另外：日志现在同时写到 `txtmux.log`（界面那份是内存的，关掉就没了）；代理每个进来的
连接都记一行 `[proxy] request host:port`，一眼能看出"是没流量"还是"进来了没命中"。

### 2026-11-18（第二批：明文通道 + 日志切分）

- **代理支持明文 `http://`**：绝对 URL 改写成 origin-form，按同一套规则/上游建连，请求头原样
  带过去，响应直接回传；强制 `Connection: close` 省掉保活/分包。指向代理自身端口的请求回 403
  （否则会经上游递归回自己）
- **日志按天切分 + 总量上限**：换天时 `txtmux.log` 改名 `txtmux-YYYYMMDD.log`；
  `txtmux-*.log` 合计超过 `logMaxMB`（默认 1024MB）时，从文件名（=日期）最旧的一份开始删，
  删到上限以内；某一天自己就超上限时，先改名，下一轮再删
- **日志写入加锁**：多线程同时写同一个文件时 `fwrite` 会交错，行首会被截掉（实测出现过
  ".0.0.1:8080（HTTP CONNECT / SOCKS5）"这种残行）
- **PAC 按「匹配域名」生成**：之前只输出解析到的目标 IP（对浏览器没用），现在精确域名用
  `host ==`、通配用 `shExpMatch`

### 2026-11-18（第三批：语义收紧 + 文档）

- **第 4 段不写 = 只做端口转发**：代理分流只认「匹配域名」，不再"自动认领"入口 URL 的域名，
  也不再拿解析出来的目标域名去比对（以前 URL 规则即使没写第 4 段也会被代理命中，属于自作主张）。
  现在 `find_rule_for_host()` 只看 `match`，PAC 也只列写了第 4 段的规则
- 实测确认（同一台机器）：
  - 只有 `rule1=open.example.com 19005 1` 时，`open.gw.*`／`webdav.gw.*` 都走上游，
    `127.0.0.1:19005` 照常转发（日志里能看到 `open.example.com -> 203.0.113.10:50002`）
  - `stun.example.com 19006 1 webdav.gw.example.com`：webdav 命中 → `:50000`，
    router 不命中 → 上游；PAC 里只有这一条
  - `stun.example.com 19007 1 *.gw.example.com`：webdav → 404、router → 403（都是同一网关
    按 SNI 分出来的），PAC 用 `shExpMatch`
- README 重写了「四种用法」一节，说明四种模式各自怎么配、怎么验证

### 2026-11-18（第四批：界面适配高 DPI）

现象：在 150% 缩放的屏幕上，标签被截断（"匹配域名(可选，"）、按钮互相压住、日志折行并且右侧被切掉。
原因：程序调了 `SetProcessDPIAware()`，字体按系统 DPI 放大，但所有控件坐标是写死的 96dpi 像素，
窗口也只有 640x508 物理像素 —— 字变大、框不变，于是全挤出去了。

改法：

- 新增 `ui()`（`MulDiv(v, g_dpi, 96)`），窗口尺寸和所有控件的位置/大小全部按系统 DPI 缩放
- 窗口改成可缩放（`WS_OVERLAPPEDWINDOW`），新增 `layout_ui(cw, ch)`：记录名/匹配域名输入框
  与规则列表、日志随宽度拉伸，日志占下方约 35% 高度，按钮行始终贴在日志上方；最小窗口 560x430
- 规则列表改用等宽字体（Consolas，缺失则回退），`:端口 → 目标` 的列对齐
- 日志框改成 `ES_AUTOHSCROLL | WS_HSCROLL`，不再自动折行（长行横向滚动，不会被切一半）

实机验证（150% 缩放，窗口 972x780 物理像素）：标签/按钮/状态 "2/2 运行" 全部完整，列表两列对齐，
日志一行一条不折行。

### 2026-11-18（第五批：日志跟随滚动）

问题：每次刷新日志都跳回顶端。原因：`SetWindowText` 会把编辑框视图复位，之后再发
`EM_SETSEL(-1,-1)` 把光标放在开头，等于永远钉在顶部。

改成 `refresh_log_view()` + 粘性跟随状态：

- 跟随时：光标移到末尾 + `EM_LINESCROLL` 到底，并记住"贴底时的首行号"
- **有焦点就不跟随**（`GetFocus() == g_edLog`，说明用户点进日志在看/选）
- **用户往上滚过就停止跟随**（首行比我们上次贴底的位置更靠前）；再滚回底部会自动恢复跟随
- 不跟随时只做两件事：把视图恢复到用户原先看的那一行、把选区恢复回去（换文本会清掉它们）
- 窗口缩放（`layout_ui`）后如果还在跟随，会重新贴底 —— 这是上一版漏掉的：缩放一次之后
  "是否在底部"的判断就失真，从此不再跟随
- 文本没变化时直接跳过，不再每条消息整体重设

实测（`EM_GETFIRSTVISIBLELINE` / `EM_GETLINECOUNT`，可见约 10 行）：

| 步骤 | 结果 |
|---|---|
| 30 次请求后（65 行） | first=56 → 56+9=65，贴底 ✔ |
| 把窗口放大 | first 自动变成 54，仍贴底 ✔ |
| 放大后再来 10 行（85 行） | first=74 → 74+11=85，仍贴底 ✔ |
| 往上滚 12 行、再来 5 行 | first 62 → 62，不动 ✔ |
| 拖回底部、再来 5 行（105 行） | first=94 → 94+11=105，恢复跟随 ✔ |
### 2026-11-18（第六批：点选即编辑 + 自动排序）

- **点列表里的规则 → 顶部编辑栏自动回填**（TXT/入口、本地端口、匹配域名）；点空白处取消选择、
  编辑栏清空。原来改一条规则得先删再重加。
- **「添加」改为「添加/修改」**：有选中就是修改那条（保留它的启用/运行状态），没有选中就是新增。
  改端口或来源才会重启监听线程（只改匹配域名不动监听）；改完自动选中该条并把它的新参数留在编辑栏。
- **允许同一个 TXT/入口被多条规则引用**：原来按"记录名唯一"拦，导致
  `stun.example.com` 既想做精确规则又想做通配规则时被拒（"记录 stun.example.com 已存在"）。
  现在只要求本地端口唯一。
- **自动排序**：规则按 `精确域名 → 通配(*) → 仅端口(没写第 4 段)` 排，稳定排序（同档内保持原顺序）。
  新增、修改后立即重排；启动加载时也会重排一次并记一行
  `规则已按「精确域名 → 通配 → 仅端口」自动排序`。这样就不用担心"通配写在精确前面导致命中错"。

实测（`WM_COMMAND`/`WM_GETTEXT` 直接驱动界面）：

| 操作 | 结果 |
|---|---|
| ini 里故意写成 通配、仅端口、精确 | 启动后顺序变成 精确(19072) → 通配(19070) → 仅端口(19071) ✔ |

| 把运行中的那条端口改成 19075，点「添加/修改」 | 日志 `已修改规则…` + `已监听 19075`；19075 在听、19070 已释放 ✔ |
